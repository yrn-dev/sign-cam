# SignCam — жестовый язык РЖЯ → текст в реальном времени

Три версии одного проекта:

- **`/`** — рабочее приложение: камера, распознавание, расшифровка.
- **`/upload.html`** — разбор готового файла: видео или фото → текст с таймкодами.
- **`/learn.html`** — учебная версия: показывает, что происходит внутри,
  на четырёх этапах, вживую на своей камере.

## Запуск

```bash
cd ~/projects/sign-cam
./venv/bin/python backend/app.py
# → http://localhost:8600
```

Первый запуск:
```bash
python3 -m venv venv
./venv/bin/pip install -r backend/requirements.txt
```

## Как это работает

```
Браузер (getUserMedia, центр-кроп 1:1)
   │  ~25 fps, JPEG 224×224, бинарный кадр (toBlob, без base64)
   ▼  WebSocket /ws
FastAPI (backend/app.py)
   │  окно 32 кадра, шаг 12 → S3D.onnx (onnxruntime, 8 потоков)
   │  усреднение softmax по 3 последним окнам
   ▼
{label, conf, ms, top[5], gesture} по WS → браузер собирает текст
```

- **Модель:** easy_sign S3D (ai-forever/Sber), 1598 жестов РЖЯ, CC-BY-SA 4.0.
  Файлы: `backend/model/S3D.onnx` + `RSL_class_list.txt`
- **Состав словаря:** ~1430 слов, 33 дактильные буквы, 11 чисел,
  123 фразы целиком («аллергия на еду»).
- **Точность модели:** 44% на окне в 32 кадра (заявлено авторами).
  Из пяти жестов уверенно распознаются два-три — это потолок модели,
  а не ошибка настройки.

### Что даёт стабильность

| Приём | Зачем |
|---|---|
| Шаг окна 12 кадров | попытка каждые 0.5 с вместо 1.3 с; жест не проваливается между окнами |
| Усреднение по 3 окнам | гасит случайные всплески («друг 93%» на пустой ладони) |
| Мгновенная фиксация при conf ≥ 75% | не требовать 2.6 с неподвижной руки |
| 8 потоков вместо 16 | 223 мс против 392 — гипертрединг мешает 3D-свёрткам |
| `toBlob` + бинарный WS | `toDataURL` блокировал поток на каждом кадре; base64 давал +33% трафика |
| Превью через `<video>`, не canvas | камера рисуется браузером, главный поток свободен |
| Пропуск кадра при `bufferedAmount` | кадры не копятся в очереди, задержка не растёт |

### Дактиль

Подряд идущие буквы система собирает в слово и сверяет со словарём
(расстояние Левенштейна ≤ 2): `доим` → предлагает `дом`. Слова не из
словаря остаются как есть — это имена и названия, их и дактилируют.

## Учебная версия

`/learn.html` показывает конвейер по этапам:

1. **Вход модели** — лента из 32 кадров 224×224 рядом с живым видео:
   буквально то, что видит S3D. Подсвечен кадр, который пишется сейчас.
2. **Решение** — топ-5 из 1598 классов, полосы уверенности, порог 50%.
3. **Сборка текста** — слова, дактиль, сверка со словарём.
4. **Где ошибается** — честные цифры точности и природа ложной уверенности.

Внешних зависимостей нет: страница работает офлайн.

## Разбор файлов

`/upload.html` принимает видео (MP4, WebM, MOV, AVI, MKV, GIF) и фото
(JPG, PNG, WebP, BMP): до 300 МБ и 3 минут. Файл разбирается в фоне,
страница показывает прогресс по окнам, а результат — текст плюс список
слов с отметками времени. Клик по слову перематывает видео на этот момент.

Важные детали реализации:

- **Приведение частоты кадров.** Любое видео прореживается до ~25 fps.
  Без этого запись с 60 fps даёт вдвое «замедленный» жест, и модель
  его не узнаёт.
- **Центральный квадрат.** Кадр обрезается по центру, как и с камеры.
- **Видео разбирают две модели.** S3D идёт по записи скользящим окном и
  даёт черновик слов. Затем запись режется на отрезки, каждый склеивается
  в сетку кадров и уходит зрячей модели: она принимает изображения, но не
  видео, поэтому отрезок превращается в контактный лист, по которому
  читается движение. Черновик S3D передаётся как подсказка. Итоговый текст
  собирается из фраз зрячей модели, слова S3D остаются черновиком.

### Как режется видео

| Параметр | Значение | Почему так |
|---|---|---|
| Предел загрузки | 180 с (3 мин) | дальше это уже пакетная задача |
| Длина отрезка | 3 с | примерно одна-две фразы жестами |
| Кадров в сетке | 16 (4×4) | кадр каждые ~190 мс |
| Отрезков максимум | 60 | 60 × 3 с = ровно 180 с, вся запись покрыта |
| Одновременных запросов | 4 | последовательно минута видео шла бы минуты |

Жест длится 1-2 секунды и попадает в 5-10 кадров сетки — движение видно.
Скорость на практике: **30 секунд видео разбираются примерно за 20 секунд**,
три минуты — около двух минут.
- **У фото свой путь.** S3D распознаёт жесты по движению между кадрами,
  и на одиночном снимке она бесполезна: 32 одинаковых кадра дают нулевое
  движение. Поэтому фотографию смотрит **мультимодальная модель зрения**
  (`gemma4` через alem.ai): она разбирает форму кисти, положение руки
  относительно лица и мимику, и возвращает жест плюс описание увиденного.
  Ответ приходит за 2-9 секунд. Ключ берётся из `.env` в корне проекта
  (`ALEM_LLM_KEY`); без него страница честно пишет, что зрение недоступно.
- **Защита от выдумок.** Модели даётся полный словарь из 1598 жестов РЖЯ
  (~5 тысяч токенов), и выбирать значение она обязана только из него.
  Отдельно запрещено называть буквой двуручный жест (дактиль РЖЯ —
  одноручный) и опираться на американский ASL. Если человека в кадре нет,
  ответ пустой.

### Провайдер зрения

По умолчанию — `gemma4` через alem.ai. Можно увести на другого, не трогая
остальное:

```bash
VISION_URL=https://openrouter.ai/api/v1 VISION_KEY=sk-or-... VISION_MODEL=... \
  ./venv/bin/python backend/app.py
```

Модель, давшая ответ, показывается на карточке результата.
- **Длинное видео** обрабатывается с удвоенным шагом окна.

## API

| Эндпоинт | Назначение |
|---|---|
| `GET /health` | провайдер, число классов, параметры окна |
| `WS /ws` | поток кадров → предсказания |
| `GET /vocab` | словарь для дактиля (1384 слова + 33 буквы) |
| `POST /upload` | загрузка видео/фото → `{job}`, разбор идёт в фоне |
| `GET /job/{id}` | прогресс и результат разбора (для фото — плюс поле `vision`) |
| `POST /translate` | смысловой слой: сетка кадров + черновик → фраза (нужен `ALEM_LLM_KEY`) |

## Требования к машине

GPU не нужен — модель рассчитана на CPU. Замеры на разном числе ядер
(одно решение по окну в 32 кадра):

| Ядер | Время решения | Хватает? |
|---|---|---|
| 2 | 726 мс | да, но поставьте `SIGNCAM_STRIDE=20` |
| 4 | 375 мс | да, комфортно |
| 8 | 222 мс | с запасом (настройка по умолчанию) |

Окно набирается 1.3 с, поэтому даже 2 ядра успевают. Важно лишь,
чтобы инференс укладывался в шаг окна: шаг N кадров = N × 40 мс.

- **Диск:** 38 МБ проект (из них 37 МБ — сама модель) + 355 МБ виртуальное окружение
- **Память:** ~600 МБ, пик около 1 ГБ
- **Python:** 3.10+
- **Интернет:** не нужен после установки — модель и фронтенд лежат локально

На слабой машине:
```bash
SIGNCAM_THREADS=4 SIGNCAM_STRIDE=20 ./venv/bin/python backend/app.py
```

## GPU (опционально)

```bash
./venv/bin/pip install onnxruntime-gpu   # нужны CUDA 12.x + cuDNN
```
